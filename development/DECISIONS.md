# Loi Compiler — Decisions

One line per decision: decision, reason, date. Language rules live in `development/LOI_SPEC.md`; current status lives in `PROGRESS.md`.

Rows dated before the 2026-11-08 cleanup may quote the surface spelling in force at the time (for example `interface`, `fun`, `in`/`out`, `move`/`copy`, `[]T`). They are historical records; the accepted syntax is canonical Flow Syntax only.

| Date       | Decision | Reason | Status |
|------------|----------|--------|--------|
| 2026-11-09 | FFI surface: `opaque Name` handles (`void *`), `cstr` (`const char *`), `extern flow` with optional `as c_symbol`, `--c-source` for shims and `--cc-flag` for include/library flags | C libraries need handles and NUL-terminated strings but Loi has no general pointers. Restricting foreign pointers to copyable, non-dereferenceable handles and C strings keeps them out of ordinary values while still allowing real calls. `--c-source` makes generated/manual shims part of the build without a second build system. | Active |
| 2026-11-09 | A string literal may initialize or be passed as `cstr`, but an arbitrary `[u8]` may not; every emitted C string literal gets a trailing NUL while the Loi slice length excludes it | A `[u8]` is not guaranteed to be NUL-terminated, so implicit coercion would read out of bounds. Adding the NUL to the C backing array makes literals safe for C without changing Loi's length semantics. | Active |
| 2026-11-09 | Generated bindings are conservative: unsafe declarations are skipped and reported, while safe struct/out-parameter conversions go through generated `memcpy` shims with `_Static_assert` layout checks | Guessing at callbacks, variadics, unions, bitfields, inline arrays, pointer-to-pointer, mutable char buffers, wide strings or unsafe record layouts would produce silently wrong calls. A shim with compile-time size/alignment assertions turns every unsupported case into a clear skip or a compile failure instead of runtime corruption. | Active |
| 2026-11-09 | `--cc-flag` values are placed after the objects on link steps; object-only compiles keep them before `-c` | Library flags such as `-lSDL2` are order-sensitive and the linker discards symbols from libraries that appear before their references. Include/define flags work in either position, so one ordering rule keeps `-l` usable without a separate flag. | Active |
| 2026-11-08 | `comptime` means "must be known at compile time" (guarantee, not hint); a `comptime flow` is pure, `<-`-only, side-effect free and step-limited | Removes the first draft's ambiguity (comptime flows called with runtime values). A guarantee is something the compiler can rely on for constant contexts; ordinary folding remains an optimization. | Decided; Phase 3 |
| 2026-11-08 | Loi has no general pointers, no `&`/`*` operators and no `nil`; graphs use integer handles, absent values use an explicit flag or sentinel, FFI pointers stay opaque at the boundary | Address-of creates a second name for one owner, contradicting the core invariant. Handles, slices and `<-` cover the real use cases without a lifetime system or a second memory model. | Decided; partial pointer code reverted |
| 2026-11-08 | `sealed` is the default visibility; `open` is the only export; `main` is implicitly exported | Least privilege and consistency with the existing `Visibility::Hidden` default, which removes the spec/AST contradiction. Cross-file enforcement remains an implementation gap. | Active |
| 2026-11-08 | Long-lived data stays in an enclosing lexical `protect`; no named-region keyword in the core | Lexical nesting already expresses lifetime, and library-level frame arenas cover reuse. Named regions would add a second lifetime system for no new capability. | Active |
| 2026-11-08 | Cyclic structures are integer handles/generation counters into an owning slice, not pointers or reference counting | Preserves single ownership, makes the owner explicit, keeps nodes compact and lets region destruction reclaim the whole graph. | Decided; stdlib helpers future |
| 2026-11-08 | Non-memory resources use linear ownership and explicit release (`<Shape>_release`), with a future `guard` block as sugar; no `defer` or hidden destructor | Fits the existing move rules, needs no unwinding, GC or methods. `guard` is sugar over the same linear rule, not a second mechanism. | Decided; not implemented |
| 2026-11-08 | Confirm implicit scalar copy and rejection of `clone` for any value containing a slice | Scalars have no identity or destructor; duplicating a slice would either alias (forbidden) or allocate without a region/length policy. `give` transfers slices; allocating duplication belongs to a future library operation. | Active |
| 2026-11-08 | Final source extension is `.loi`; `.lum` is abandoned; canonical reference is `examples/particles.loi` | Implementation, examples and tests already use `.loi`; two extensions add no value. The plural reference file already exists and should not be renamed. | Active |
| 2026-11-08 | Standard functions are a small closed reserved intrinsic set plus the explicitly imported `lib/std.loi`; no implicit prelude | Intrinsics are only what the backend/OS must provide; everything else grows in Loi without changing the compiler. `len` is now reserved like `print` and the math intrinsics. | Active |
| 2026-11-08 | Adopt "Loi Flow Syntax" as the only surface: `shape`/`flow`, `<-`/`->`/`<->`, `=>`, `[T]`, `Name[ ... ]`, `mut`, `give`/`clone`, `open`/`sealed`; `fmt` emits Flow Syntax | The legacy surface borrowed Rust vocabulary. The new one makes directions, ownership transfer and regions visible in every declaration. The additive and transitive phases ended with the legacy forms removed. | Active, complete |
| 2026-11-08 | Function signatures may be vertical clause lists (`flow f` then `<- x: T`, `=> R`, then `{`); the result clause and the result statement both use `=>` | A vertical signature makes each direction a line and avoids a heavily punctuated single-line signature. `=> T` in the header is a clause; `=> v` in a body is unambiguous because a statement cannot begin a signature. | Active |
| 2026-11-08 | Explicit slice literals are `[T: a, b]` (`[T:]` when empty); inferred literals are `[a, b]`; the brace form `[]T{...}` is not accepted | Keeps brackets for data and reuses the colon that shape literals already use. The parser backtracks after trying a type so `[a, b]` and indexed expressions remain unambiguous. | Active |
| 2026-11-08 | Canonical `fmt` omits `sealed` and emits `open` only for exported items; bracket shape literals need no header parentheses | The default is sealed, so printing it would add noise. `Name[ ... ]` cannot be confused with the `{` block opener, so the old parenthesization rule is unnecessary. | Active |
| 2026-11-08 | Complete the cleanup phase: remove the legacy keywords, `&`, brace shape literals and `[]T{...}` slice literals after the transitive port | The transitive port made every maintained source canonical. Keeping two surfaces would preserve two spellings for one semantics and keep dead parser paths alive. The reference `examples/particles.loi` is now byte-identical to `examples/flow_syntax.loi`, and the compatibility tests were retired. | Done |
| 2026-11-05 | Implement the compiler in Rust, using Cargo and the standard test framework | Python only served as a fast prototype. The advanced roadmap (freshness/instruction counting, spatial tiers, quality code generation) needs a systems language with predictable performance and a strong long-term ecosystem. This supersedes the Python implementation. | Active |
| 2026-11-05 | Remove the Python prototype (`src/loi/`, `tests/test_lexer.py`) instead of keeping two implementations | A second front end would become stale and create ambiguity about the source of truth. The migration is recorded here. | Active |
| 2026-11-05 | Use a Cargo package with a library (`src/lib.rs`) plus a small binary (`src/main.rs`) | The library exposes lexer/parser/AST to integration tests and future stages; the binary provides a reproducible CLI. | Active |
| 2026-11-05 | Keep the stage modules separate: `token.rs`, `lexer.rs`, `ast.rs`, `parser.rs` | Required by the spec's modularity rule; later stages get `types.rs` and `codegen.rs`. | Active |
| 2026-11-05 | The lexer emits `Newline` tokens and collapses consecutive blank lines | Interface fields and call arguments may be separated by newlines, so the parser needs explicit line boundaries. | Active |
| 2026-11-05 | Tokens carry 1-based line and column positions; the stream always ends with `Eof` | Clear diagnostics and a simple parser contract. | Active |
| 2026-11-05 | Longest-match operators are implemented with a two-character table checked before single characters | Required by `LOI_SPEC.md` section 7 (`..`, `->`, `+=`, `==`, ...). | Active |
| 2026-11-05 | Numeric literals accept `_` separators and exponents in addition to decimals | The spec does not define numeric grammar yet; this is a small, conventional extension recorded in `PROGRESS.md`. | Active |
| 2026-11-05 | Keep the reference file at `examples/particles.loi` instead of renaming it | Do not overwrite user-provided files; the spec filename mismatch is documented in `PROGRESS.md`. | Active |
| 2026-11-05 | Use a recursive-descent parser and model the AST without spans for now | Recursive descent matches the small, regular grammar. Parser errors already carry token positions; source spans can be added when the type checker needs them. | Superseded by the AST-span decision below |
| 2026-11-05 | Disable interface-literal parsing in `if`/`while`/`for` headers unless parentheses make it unambiguous | `if x {` must treat `{` as the block opener, not as a literal. Parenthesized literals remain possible. | Active |
| 2026-11-05 | Model `move`, `copy` and `alloc` as dedicated AST nodes | The spec says `move` is compiler intrinsic syntax, not an ordinary call; `alloc` also takes a type argument that is not a value expression. | Active |
| 2026-11-05 | Pretty-print with four-space indentation, one statement per line and minimal parentheses | Produces canonical, readable output and preserves the AST without needing to keep original whitespace. | Active |
| 2026-11-05 | Parenthesize interface literals inside `if`/`while`/`for` headers | Parentheses make the literal unambiguous against the block opener; the parser otherwise disables literals in those headers. | Active |
| 2026-11-05 | Do not preserve comments in the pretty-printer for now | Comments are discarded by the lexer and are not part of the AST; preserving them would require trivia tokens. | Active |
| 2026-11-05 | Provide a small CLI (`loi lex FILE`, `loi parse FILE`, `loi fmt FILE`) | Gives a reproducible way to verify each stage against the reference program. | Active |
| 2026-11-05 | Every statement, expression, declaration, field and parameter carries a 1-based start `Span { line, column }` | Semantic diagnostics must point at the offending construct; storing only the start keeps the AST small while positions remain accurate enough for errors. | Active |
| 2026-11-05 | Resolve declarations in three passes: collect names, resolve interfaces/signatures, then check bodies | Allows interfaces and functions to refer to declarations that appear later, while still checking each body after all types are known. | Active |
| 2026-11-05 | Use a semantic `Ty` with `IntLiteral`, `FloatLiteral`, `Void` and `Error` in addition to concrete types | Unsuffixed literals need contextual coercion; `Error` suppresses cascading diagnostics after an earlier error. | Active |
| 2026-11-05 | Unsuffixed integer literals coerce to any numeric type; float literals coerce to float types; named numeric widths never convert implicitly | The reference program passes integer literals where `f64`/`u64` are expected. Requiring explicit casts between named widths keeps the type system predictable. | Active |
| 2026-11-05 | Track `mutable` and `initialized` in variable symbols, including `let`, `var`, `in`, `out` and `inout` | Implements the spec's read-only `in`, uninitialized `out`, and immutable `let` rules without needing a full borrow or ownership analysis yet. | Active |
| 2026-11-05 | `move` from an `in` parameter or an uninitialized variable is a type error; `copy` rejects types containing a slice recursively through interfaces | Follows `LOI_SPEC.md` sections 4.2 and 4.3. Actual move-liveness and aliasing are deferred to Phase 2. | Active |
| 2026-11-05 | Add `loi check FILE`, which prints all semantic diagnostics as `path:line:column: message` and exits 1 on errors | Gives a reproducible way to verify the type checker and matches the diagnostics produced by the library. | Active |
| 2026-11-05 | Defer definite-return analysis and `alloc`/`protect` escape checks to Phase 2 | Keep Phase 1 focused on types and directions; these checks depend on ownership and control-flow analysis that belongs to the memory phase. | Active |
| 2026-11-05 | Represent ownership locations as `(variable, relative path)` strings such as `w.particles` and `xs[]`; moves kill only overlapping paths | Gives useful path sensitivity (`move(w.particles)` leaves `w.gravity` alive) without a separate borrow checker or lifetimes. Path prefixes respect component boundaries so `a` does not overlap `ab`. | Active |
| 2026-11-05 | Join definite assignment with intersection and move state with union; loops are treated as possibly executing zero times; branches ending in `return` do not participate in the join | A variable is readable only if initialized on every continuing path; treating a value moved on any continuing path as dead is conservative and avoids unsound reuse. | Active |
| 2026-11-05 | Enforce `out`/`inout` exclusivity by comparing ownership paths, not whole variable roots; duplicate `in` arguments are allowed | Follows the spec's "no other use of it" per value, so `mix(inout v.x, v.y)` is allowed while `swap(inout v, inout v)` is rejected. | Active |
| 2026-11-05 | Reject implicit copies of composite place expressions in `let`, plain assignment and interface-literal fields; allow `move`, `copy`, call results and literals | Implements the spec rule that composite values have one owner and are never copied implicitly, while scalars keep implicit copy. | Active |
| 2026-11-05 | Reject returning a composite place rooted at an `in` parameter unless wrapped in `copy(...)` | Follows the spec rule that an `in` parameter is read-only and cannot be stored or returned; `inout` and local composites remain returnable. | Active |
| 2026-11-05 | A whole-variable write clears all moved paths; a partial write into moved storage is rejected unless it exactly reinitializes the moved path | Allows `a = move(b); a = 2` and writing back `w.particles`, but catches `v.x = 1` after `move(v)`. Immutability is still enforced for already-initialized variables. | Active |
| 2026-11-05 | Model `protect` regions as IDs with parent links; variables carry a `home_region`; allocations taint ownership paths instead of whole variables | A destination is safe when its home is the source region or a nested region, so escapes are rejected without forbidding writes to outer storage. Path taints keep `w.particles` and `w.gravity` independent. | Active |
| 2026-11-05 | Allow unguarded `alloc` only in non-entry functions; compute function allocation effects with a fixed-point prepass and require entry functions (`main` and uncalled functions) to allocate inside `protect` | Matches the spec rule that a callee's allocation belongs to the caller's nearest `protect`; the reference `world_new` is valid when called from `main` inside `protect`. | Refined |
| 2026-11-05 | Track allocation taints through `let`, assignment, `move`, interface literals, `out` arguments and `return`, but not through `in`/`inout` arguments or arbitrary callee bodies | Covers the common escape routes while keeping the analysis intraprocedural. The remaining gap is recorded in `PROGRESS.md`. | Refined |
| 2026-11-05 | Reject non-void functions whose body can fall through, reusing the existing reachability flag; loops are treated as possibly executing zero times | Reuses branch-aware reachability instead of a second control-flow analysis. The conservative loop rule is recorded in `PROGRESS.md`. | Active |
| 2026-11-05 | Summarize which parameters a function consumes and mark matching `out`/`inout` call arguments moved; returning a composite place also transfers ownership | Keeps single ownership across calls without interprocedural borrow checking. Whole-parameter summaries are conservative; the limitation is recorded in `PROGRESS.md`. | Active |
| 2026-11-05 | Propagate protect-region taints from consumed `inout` arguments to slice-containing `out` arguments and composite call results, checking escape at each destination | Closes the escape hole where a callee forwards protect-local data into caller storage. Over-tainting is preferable to missing an escape; the limitation is recorded in `PROGRESS.md`. | Active |
| 2026-11-05 | Refine allocation entry points: `main` and uncalled visible/default functions are entries; uncalled `hidden` helpers may rely on a caller's `protect` | `hidden` means the function is not externally reachable, so an unguarded `alloc` there is covered by whichever Loi caller provides the region. Uncalled visible functions remain entries because external code could call them directly. | Active |
| 2026-11-05 | Confirm the Phase 2 provisional rules: scalars copy implicitly, duplicate `in` arguments are allowed, `copy` of a slice-containing value is rejected, and returning a composite place transfers ownership while returning from an `in` parameter requires `copy(...)` | These rules were already implemented and tested; recording them closes the Phase 2 review and matches spec 4.3/4.4. `copy` remains a deep-copy primitive that cannot invent a slice length or allocation region. | Active |
| 2026-11-05 | Declare Phase 2 complete for the front end and defer runtime slice bounds checks to Phase 4 code generation | The checker types slices and enforces ownership, but executing `xs[i]` needs generated code. Keeping bounds checks with codegen avoids inventing a runtime or interpreter now; the deferral is recorded in `PROGRESS.md`. | Active |
| 2026-11-05 | Target C11 as the first backend, emitting a single translation unit with `stdint.h`/`stdbool.h`, plain `struct`s for interfaces and a `{ void* data; size_t len; }` slice | C is the spec's first target, compiles everywhere, and keeps the first backend small enough to verify end to end. Generated names are prefixed (`loi_fn_`, `loi_t_`, `loi_f_`, `loi_v_`, `loi_tmp_`) while Loi `main` maps to C `main`. | Active |
| 2026-11-05 | Pass `in` parameters by value, `out`/`inout` parameters by pointer; initialize `out` composites from interface field defaults on function entry | The checker already forbids storing or returning borrowed values, so copying is an implementation detail in single-threaded code. Default initialization is required because `world_new` writes only some `World` fields but `World.tick = 0` must still hold. | Active |
| 2026-11-05 | Lower `protect` to a global 64 MiB bump arena, saving/restoring `loi_arena_top` on block exit, `continue` and `return`; evaluate a `return` value into a temporary before restoring | A single offset implements nested regions cheaply, and a callee's allocations naturally belong to the nearest caller region. The temporary keeps the return value readable after the region is logically released. Non-thread-safe, fixed-size behavior is recorded in `PROGRESS.md`. | Active |
| 2026-11-05 | Emit runtime slice bounds checks through `loi_index(LoiSlice, size_t, size_t)`, taking the slice header by value | Passing the header by value lets the helper check the length while evaluating the base expression only once, including for nested index expressions. | Active |
| 2026-11-05 | Mark generated helper functions `static inline` (Loi functions and runtime helpers) while `main` stays plain | Keeps internal linkage but avoids `-Wunused-function` failures for valid Loi programs that declare helpers they do not call, so generated C is usable with `-Werror`. | Active |
| 2026-11-05 | Order interface `struct` definitions by value dependency and reject value cycles in the backend | C requires a complete type before a by-value field, and the checker does not diagnose recursive interface layout. The backend error is preferable to emitting invalid C. | Active |
| 2026-11-05 | Add `loi gen FILE`, which tokenizes, parses, checks and only then prints C | Keeps the CLI reproducible and prevents the backend from receiving semantically invalid programs; `generate_c` itself documents that it assumes a checked `Program`. | Active |
| 2026-11-05 | Reject an unsupported `main` in the backend: no parameters, and the return type must be absent or an integer | The emitted entry point is C `int main(void)`, so a composite or floating return would produce invalid or misleading C. The checker still accepts a broader `main`; the backend error is explicit. | Active |
| 2026-11-05 | `loi gen FILE -o OUTPUT` writes the C file and stays silent; without `-o` it prints to stdout | Keeps the existing pipeline/pipe behavior while giving a non-shell way to create a translation unit. Only `gen` and `build` accept `-o`; other modes report usage error 2. | Active |
| 2026-11-05 | `loi build FILE [-o EXE]` invokes `cc` (or `$CC`) on a temporary generated C file, defaults the executable to `./a.out`, and deletes the temporary file | Gives a runnable pipeline without embedding a C compiler or changing the backend. `$CC` is conventional and the temporary file avoids leaving build artifacts next to the source. The temporary file and fixed `-std=c11` policy are recorded in `PROGRESS.md`. | Active |
| 2026-11-05 | Lower `alloc` to `loi_alloc_slice(count, element_size)` in both statement and expression positions | Removes the statement-only special case and the expression fallback that evaluated the count twice. A helper returning the complete `LoiSlice` keeps both positions identical and makes the allocation policy explicit. | Active |
| 2026-11-05 | Check `SIZE_MAX` before alignment and before `count * element_size` in the arena helpers; abort with a distinct diagnostic on overflow | The previous helpers wrapped silently on huge sizes. Explicit checks turn integer overflow into a deterministic runtime error instead of an undersized allocation. | Active |
| 2026-11-05 | Use `uint64_t` range-loop induction when the checked common bound type is `u64`; otherwise use `int64_t` | `int64_t` cannot represent `u64` bounds above `i64::MAX`. Selecting the C type from the checked Loi type keeps the loop domain correct while leaving all other integer widths on one signed path. | Active |
| 2026-11-05 | `loi gen -o` and `loi build -o` reject an output path lexically equal to the input path | Truncating the source would destroy the only copy of the program. An early usage error (exit 2) is safer and clearer than letting the write overwrite the input. | Active |
| 2026-11-05 | `-h`/`--help` prints usage and exits 0; `-V`/`--version` prints `loi <cargo version>` and exits 0 | Conventional CLI behavior, and the version comes from `CARGO_PKG_VERSION` so it cannot drift from the package metadata. | Active |
| 2026-11-05 | `loi build --emit-c PATH` writes the generated C at `PATH` and leaves it there, instead of using a temporary file; it may not equal the input or the executable | Retaining C is needed to inspect or debug code generation without rerunning `loi gen`. Reusing the temp-file path would make retention confusing, and the equality guards prevent overwriting the source or the binary with C. | Active |
| 2026-11-05 | `loi build --cc-flag FLAG` (repeatable) forwards one argument to the C compiler after `-std=c11` | Gives access to optimization, warning and linker flags without parsing a shell string. Repeating the option keeps argument boundaries explicit; tool arguments belong in `$CC` instead. | Active |
| 2026-11-05 | `loi build --emit exe\|obj\|lib` selects an executable, a relocatable object (`cc -c`) or a static archive (temporary object plus `ar rcs`); `exe` is the default | One build command covers the three artifacts users need for linking and packaging. Keeping `-o` as the output path for all kinds avoids a second naming option, and `obj`/`lib` are short aliases for `object`/`library`. | Active |
| 2026-11-05 | Without `-o`, object output defaults to `<input stem>.o` and library output to `lib<input stem>.a`; executables still default to `./a.out` | Conventional artifact names make `loi build --emit obj foo.loi` usable without extra flags. The stem keeps the name derived from the source instead of a fixed `output.o`. | Active |
| 2026-11-05 | Static-library builds invoke `$AR` (default `ar rcs`) on a temporary object and remove it afterwards; `--cc-flag` values apply only to compilation, not to `ar` | `ar` is the portable way to create a `.a` archive and is normally installed with the C toolchain. Not forwarding C flags to the archiver avoids confusing failures from options `ar` does not understand. | Active |
| 2026-11-05 | `loi build --debug`/`-g` passes `-g`; `--release` passes `-O2`; the profiles are mutually exclusive and rejected outside `build` | Fixes a small, documented default policy instead of making users spell common flags through `--cc-flag`. Placing the profile flag before user flags lets `--cc-flag` override it deliberately. Conflict detection avoids ambiguous command lines. | Active |
| 2026-11-05 | `loi build` is incremental by default: it stores an FNV-1a fingerprint of the generated C, tool paths, artifact kind, profile and flags in `<output>.loi-stamp`, and skips the compiler when the output, retained C and stamp all match | Avoids recompiling a 1:1 translation unit when nothing changed, without an external build system. Content hashing is robust against checkout/mtime changes; writing the stamp only after success means failures always retry. The sidecar and its blind spots are recorded in `PROGRESS.md`. | Active |
| 2026-11-05 | `loi build --rebuild` forces the toolchain even when the stamp matches, and is rejected outside `build` | Gives a deterministic escape hatch when the environment changed in ways the fingerprint cannot see (toolchain replaced in place, manual edits to retained C). The stamp is still refreshed after the forced build. | Active |
| 2026-11-05 | `loi clean FILE [-o OUTPUT]` deletes artifacts and `.loi-stamp` sidecars without reading or checking the source; default outputs are removed only when their stamp exists, while `-o` is explicit | Cleaning must work when the source is broken or temporarily absent, so it cannot parse the file. Stamp gating avoids deleting unrelated files such as a generic `a.out`; `-o` gives the user an explicit way to target custom outputs. | Active |
| 2026-11-05 | `CC`/`AR` values are split into a program plus arguments with POSIX-shell-like rules (whitespace, single/double quotes, backslash escapes); extra arguments precede Loi's own compiler/archiver flags and participate in the incremental fingerprint | A single-executable-path restriction breaks common wrappers (`ccache cc`, `distcc ...`, cross-compiler prefixes) and tool paths containing spaces. Shell-like parsing is familiar and avoids invoking a shell, so no redirection/expansion is introduced. Empty values and empty programs are rejected rather than silently falling back to `cc`/`ar`. | Active |
| 2026-11-05 | Statement-position `alloc` captures the target address, then the count into a `size_t` temporary, then stores through the pointer | Removes reliance on C's unspecified evaluation order between the assignment target and the count expression. The target is evaluated once, the count once, and the store is explicit; a checked `alloc` is `void`, so only statement position is reachable. | Active |
| 2026-11-05 | The `.loi-stamp` file records the retained `--emit-c` path on a second, percent-encoded line; `loi clean` removes it and stamp matching requires the same path | Lets cleaning remove generated C without guessing filenames, and makes switching `--emit-c` targets force a rebuild even when the new path already exists. Keeping the fingerprint on the first line preserves compatibility with older stamps, which simply have no retained C. | Active |
| 2026-11-05 | Check integer literals against the expected fixed-width integer type at every typed position, including binary operands whose width is fixed by the other side; untagged inference uses the provisional `i32` default | Without the check, `let x: u8 = 256`, `u64 > -1` and `return 5000000000` from an `i64`-typed context would silently truncate or rely on C's conversion rules (a negative literal compared with an unsigned value becomes a huge unsigned value). Checking the value catches the common mistake at compile time. Explicit `as` casts stay unchecked because truncation is their purpose; literal-only integer arithmetic is folded for this check. | Active |
| 2026-11-05 | Fold literal-only integer expressions with `i128` arithmetic for diagnostics, saturating on overflow, and report constant division/remainder by zero | Makes the range check catch `let x: u8 = 200 + 100` and similar expressions instead of leaving them to C wraparound, without requiring a full constant evaluator. `i128` covers `u64::MAX` and `i64::MIN`; saturation keeps larger results outside every supported type so they are rejected rather than silently wrapped. Folding is diagnostic-only, so code generation is unchanged. Constant zero divisors are always a runtime fault, so rejecting them early is safe. | Active |
| 2026-11-05 | Pass line/column constants to `loi_index`, `loi_alloc_slice` and `loi_alloc` so runtime failures print `loi: <message> at <line>:<column>` | A runtime abort with no location makes debugging compiled programs hard. The helpers already call `exit(1)`; adding the source position to the message keeps the abort behavior while identifying the offending Loi expression. Codegen inserts `expr.span.line`/`expr.span.column` at each call site. | Active |
| 2026-11-05 | Diagnose shape value cycles in the checker instead of only in the backend | A cycle of shapes that contain each other by value (e.g. `shape A [ b: B ]` / `shape B [ a: A ]`, or `shape A [ a: A ]`) cannot be laid out as a C struct. Detecting it in the checker gives a clear source-positioned diagnostic instead of a generic backend error. Slice fields (`[B]`) do not create a value dependency. | Active |
| 2026-11-05 | Runtime/I/O surface via intrinsics: `print(<- [u8])` → `fwrite(data, 1, len, stdout)`, `sqrt(<- f64) => f64` → `sqrt(x)` from `<math.h>`, link executables with `-lm` | At the time, spec question 9 left standard functions undefined; this was a temporary, minimal decision to unblock I/O and math without inventing library semantics. Intrinsics map 1:1 to existing C standard library functions and are pre-declared in the checker with fixed signatures. Later finalized by the 2026-11-08 two-tier decision (5.9). | Active |
