Program like data flows.

Loi is a compiled systems language where every signature states what comes in and what goes out. Brackets are data, braces are scopes, arrows are movement. One owner, no lifetimes, no borrow checker.

particle.loi 
shape Vec2 [ x: f64, y: f64 ]

shape Particle [
    pos:   Vec2
    vel:   Vec2
    alive: bool = true
]

open flow step
    <-> p: Particle
    <- dt: f64
{
    p.pos.x += p.vel.x * dt
    p.pos.y += p.vel.y * dt

    if p.pos.y < 0 {
        p.alive = false
    }
}

open flow main
    => i32
{
    mut p: Particle <- Particle[
        pos: Vec2[ x: 0, y: 10 ],
        vel: Vec2[ x: 2, y: -1 ],
    ]

    step(<-> p, 1.0)
    print("particle updated\n")
    => 0
}

Why Loi

The language tells you where the data goes.

Loi removes the hidden parts of systems programming: implicit copies, borrowed-forever values and cleanup you have to remember. The shape of a declaration is the shape of its data flow.

Arrows, not guesswork

Every parameter declares <-, -> or <->. Calls mark writes, so a reader can see which arguments will change.

Ownership without lifetimes

One live name per value. Transfer with give(x), duplicate explicitly with clone(x). No garbage collector and no borrow checker.

Regions, not leaks

protect { } owns every allocation inside it. When the block ends, its memory dies as a region — no per-value destructors, no defer.

Shapes are data

shape Vec2 [ x: f64, y: f64 ] declares a named record with defaults and no methods. Literals use brackets: Vec2[ x: 1, y: 2 ].

A small, closed core

A fixed intrinsic set covers I/O, math and len. Everything else grows in lib/std.loi, written in Loi itself.

A real, inspectable compiler

Lex, parse, format, check, emit C, build and run. The pipeline is deliberately small enough to read, test and extend.

The Flow Syntax

Read the direction of every value.

Loi's surface is built from three ideas: braces delimit scopes, brackets delimit data, and arrows show movement. The same glyphs appear in declarations, calls and loops.

  • <- reads, -> initializes, <-> reads and writes.
  • x <- v binds immutably; mut x <- v allows assignment.
  • => value is the result flowing out; there is no return keyword.
  • open exports; sealed is the default.
Language tour
directions.loi 
// A flow declares its data flow up front.
open flow normalize
    <- value: f64        // read-only view
    -> out: f64          // caller's variable is initialized
    <-> total: f64       // read and write
    => f64               // single result
{
    total += value
    out = value / total
    => out
}

open flow main
    => i32
{
    mut sum: f64 <- 0
    mut ratio: f64

    normalize(10, -> ratio, <-> sum)
    print("normalized\n")
    => 0
}

Quick start

From source to executable in three commands.

$ cargo build
$ ./target/debug/loi --version
$ ./target/debug/loi check examples/tictactoe.loi
$ ./target/debug/loi build examples/tictactoe.loi -o tictactoe
$ ./tictactoe
$ cargo build
$ node website/server.mjs
# open http://localhost:4173/playground.html

No hidden runtime

Compile it, read the C, run the binary.

Loi's production backend emits one C11 translation unit and invokes the system C compiler. There is no VM, no package manager dependency and no runtime framework.

  • loi gen writes the generated C you can inspect.
  • loi build --emit exe|obj|lib produces executables, objects or archives.
  • loi fmt is the canonical formatter for the only accepted syntax.
