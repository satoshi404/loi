Loi documentation

Loi is a compiled systems language built around explicit data flow, single ownership and lexical memory regions. This documentation describes the only accepted surface, Loi Flow Syntax, and the compiler as it exists today.

Getting started

Loi is a Rust workspace with a library and a CLI. The compiler emits C11 and invokes the system C compiler to produce a native executable. The playground is a small Node server that drives the same compiler, so no WebAssembly toolchain is needed.

Requirements

  • A recent stable Rust toolchain (the crate uses the 2024 edition).
  • A C compiler available as cc (or through CC) for loi build.
  • Node 18 or newer only if you want to run the local playground server.
terminal
cargo build
./target/debug/loi --version

The compiler has no third-party Rust dependencies. On unusual toolchains you may need to point Cargo at a working linker, for example RUSTFLAGS="-C linker=/usr/bin/gcc".

Hello, Loi

Create hello.loi:

hello.loi
shape Greeting [
    message: [u8]
    times:   u32
]

open flow greet
    <- greeting: Greeting
{
    for i in 0..greeting.times {
        print(greeting.message)
    }
}

open flow main
    => i32
{
    greet(Greeting[ message: "Hello, Loi!\n", times: 3 ])
    => 0
}
terminal
./target/debug/loi check hello.loi
./target/debug/loi build hello.loi -o hello
./hello
No hidden runtime. loi gen prints the generated C, so you can read exactly what the language lowers to before compiling it.

Language tour

The surface follows one principle: braces are scopes, brackets are data, arrows are movement. A declaration shows where each value goes, and calls repeat those arrows at the call site.

GlyphMeaning
<-Read-only direction. Also binds a new immutable name.
->Write/initialize direction. Marks the caller's variable at a call.
<->Read-write direction. Explicitly exclusive during a call.
=>The result flowing out of a flow. Replaces return.
[ ]Data: shape bodies, shape literals, slice types and slice literals.
{ }Scope: flow bodies, blocks and protect regions.

Shapes

A shape is a named record with fields and optional defaults. Shapes have no methods. Field separators may be commas or newlines.

shapes.loi
shape Vec2 [ x: f64, y: f64 ]

shape Particle [
    pos:   Vec2
    vel:   Vec2
    mass:  f64
    alive: bool = true
]

mut p: Particle <- Particle[
    pos: Vec2[ x: 0, y: 10 ],
    vel: Vec2[ x: 2, y: -1 ],
]

A literal always carries its shape name and uses brackets. A field with a default may be omitted. shape Name [] is the empty shape.

Flows

Functions are called flows. Every parameter declares a direction. The signature may be written on one line or vertically; the vertical form is canonical when there is more than one clause.

directions.loi
open flow normalize
    <- value: f64        // read-only view
    -> out: f64          // caller's variable is initialized
    <-> total: f64       // read and write
    => f64               // single result
{
    total += value
    out = value / total
    => out
}

open flow main
    => i32
{
    mut sum: f64 <- 0
    mut ratio: f64

    normalize(10, -> ratio, <-> sum)
    print("normalized\n")
    => 0
}

A flow may declare any number of -> parameters and at most one => T result. => T is conceptually a hidden out-flow. A flow with no result can use a shorter header such as flow f {.

Bindings and assignment

bindings.loi
answer <- 42                  // immutable
mut total: i64 <- 0           // mutable, explicit type
mut pending: Vec2             // uninitialized: only valid as ->
pending = Vec2[ x: 1, y: 2 ]  // assignment after initialization

total += 10                   // +=, -=, *= and /= are supported
count <- total as i32         // numeric cast with `as`

An uninitialized binding exists but cannot be read until it has been written or passed through a -> parameter. Shadowing is scoped like any other binding.

Expression rules

Expressions support arithmetic (+, -, *, /, %), bitwise operators (&, |, ^, ~), shifts (<<, >>), comparisons, the boolean operators and, or and not, unary negation and as casts. There is no assignment inside an expression and no ++/--. Compound assignment includes %=, &=, |=, ^=, <<= and >>=.

Bitwise operators require integer operands; they do not accept bool. Shift counts must be in [0, width) and an out-of-range count traps. Left shifts wrap at the declared width; unsigned right shifts are logical and signed right shifts are arithmetic. Precedence, from lowest to highest, is or, and, comparisons, |, ^, &, shifts, additive, multiplicative, casts, unary.

== and != are defined for scalar numeric types, bool and [u8]. Byte slices compare structurally. Other shapes and slices must be compared field by field.

Integer arithmetic is checked. Signed +, -, * and unary - trap on overflow; unsigned arithmetic wraps at its declared width. / and % trap on a zero divisor, MIN / -1 traps, and MIN % -1 is 0. A trap prints loi: <message> at <line>:<column> and exits with status 1. Literal-only expressions are folded, so a constant overflow or zero divisor is reported at compile time. as remains an unchecked truncating cast.

Number and string literals

literals.loi
dec <- 1_000_000
hex <- 0xFF
bin <- 0b1010_0101
ratio <- 1.5
small <- 1e-3

name <- "Loi\n"
raw <- "tab:\tquote:\"slash:\\"
byte <- "\x4c"              // ASCII escape, type [u8]

String escapes are \n, \t, \r, \0, \\, \" and ASCII \xNN. A string has type [u8], holds decoded UTF-8 bytes and carries no implicit trailing NUL.

Control flow

control.loi
if value > 0 {
    print("positive\n")
} else if value < 0 {
    print("negative\n")
} else {
    print("zero\n")
}

mut i: i32 <- 0
while i < 3 {
    i += 1
    if i == 2 {
        continue
    }
    if i == 3 {
        break
    }
}

for n in 0..10 {            // half-open range
    print(".")
}

for <- item in items {      // read each element
    print(item.name)
}

for <-> item in items {     // mutate each element
    item.value += 1
}

=> 0                        // the result flows out

Slices

Slice types are written [T]. The explicit literal is [T: a, b, c]; an inferred literal is [a, b, c]; the empty literal is [T:]. len(xs) and xs.len both return a u64. Indexing is bounds-checked at runtime.

slices.loi
explicit: [i32] <- [i32: 1, 2, 3]
inferred <- [4, 5, 6]
empty: [u8] <- [u8:]

mut total: i32 <- 0
for i in 0..len(explicit) {
    total += explicit[i]
}
Literal lifetime. A slice literal's backing array has automatic storage in the enclosing lexical block. It must not escape that block: the checker rejects returning it, assigning it to a variable declared outside the block, or embedding it in a shape that then escapes. If the data must outlive the block, allocate it inside a protect region with alloc.

Globals and imports

A top-level binding is a global. It is initialized once, before any flow runs, and its initializer must be a compile-time constant. Imports are textual: import "lib/std.loi".

globals.loi
import "lib/std.loi"

GREETING: [u8] <- "hello from Loi\n"
LIMIT: i32 <- 3
mut counter: u64 <- 0

open flow main
    => i32
{
    print(GREETING)
    if not str_starts_with(GREETING, "hello") {
        => 1
    }
    => 0
}

Relative imports resolve from the importing file's directory. A file is visited at most once per compilation unit, so diamond imports do not duplicate declarations. Visibility is not yet enforced across files; that is an implementation gap, not a language rule.

Visibility

open exports a declaration. sealed is the default and may be written for emphasis. Visibility applies to flows, shapes and globals. main is the implicit entry point.

Ownership & memory

Loi has no garbage collector and no borrow checker. It has one rule instead: every value has exactly one owner and one live name.

Transfer and duplication

ownership.loi
shape Point [ x: i32, y: i32 ]

point <- Point[ x: 10, y: 20 ]
copy  <- clone(point)      // explicit deep duplicate
other <- give(point)       // ownership moves; `point` is now dead

// print(point.x)          // compile error: use of moved value
print(other.x)
  • give(x) transfers ownership and kills x.
  • clone(x) duplicates composite values explicitly.
  • clone of a value containing a slice is rejected: two names must not alias the same backing array.
  • Scalars (i32, f64, bool, ...) copy implicitly because they have no identity and no destructor.
  • Composite values never copy implicitly.

Borrows are scoped views

A <- parameter is a read-only view of the caller's value. It can be read but never stored or returned. To keep part of it, clone that part. A <-> parameter is exclusive for the duration of the call: no other use of the same value is allowed in that call. Passing the same value twice as <- is allowed because both are reads.

Regions and protect

Allocation happens only inside a protect block. Everything allocated there belongs to that region and dies when the block ends. Nothing allocated inside may escape. Code inside may write into memory that existed before the block; that is how results get out.

regions.loi
open flow main
    => i32
{
    mut total: i32 <- 0

    protect {
        mut xs: [i32]
        alloc(-> xs, i32, 4)
        xs[0] = 1
        xs[1] = 2
        xs[2] = 3
        xs[3] = 4
        for i in 0..len(xs) {
            total += xs[i]
        }
    }   // xs and its backing array die here

    print("done\n")
    => 0
}
  • alloc(-> xs, T, n) allocates n elements of T.
  • alloc outside any protect is a compile error. There is no manual free.
  • An allocation made by a called flow belongs to the nearest enclosing protect of the caller.
  • Region taint is checked: allocated data cannot be returned or stored past the block.
  • The arena grows in chunks. --arena-size BYTES sets the first chunk (default 64 MiB), not a hard limit; later chunks grow geometrically, and a single oversized allocation gets a dedicated chunk. Existing slices stay valid because chunks are never moved.

No pointers

Loi has no general-purpose pointers, no address-of (&expr) or dereference (*p) operators and no nil. & is only the bitwise AND operator. Graphs use integer handles into an owning array; absent values use an explicit flag or a sentinel; foreign pointers stay opaque at the FFI boundary. This avoids a second memory model and the lifetime rules that address-of would require.

Resources

Whole-file and whole-stdin I/O is available through the read_file, write_file, read_stdin and read_line intrinsics. A linear-resource design for long-lived files, sockets and other handles (guard plus a compiler-known <Shape>_release) is specified but not implemented yet. There is no network, directory, seek, environment or process API.

Standard library

Loi has two tiers: a small, closed set of compiler intrinsics that are always available, and lib/std.loi, which is ordinary Loi and must be imported explicitly. There is no prelude.

lib/std.loi

Import it with import "lib/std.loi". The library is deliberately prefixed by kind.

GroupFunctions
Integers min_i32, max_i32, abs_i32, clamp_i32 — all <- i32... => i32
Floats min_f64, max_f64, abs_f64, clamp_f64 — all <- f64... => f64

stdlib.loi
import "lib/std.loi"

open flow main
    => i32
{
    low <- min_i32(3, 8)
    high <- clamp_i32(100, 0, 10)
    found <- str_find("hello", "ll")

    if low != 3 or high != 10 or found != 2 {
        => 1
    }

    print("standard library ok\n")
    => 0
}

New functionality belongs in the library by default. An intrinsic is added only when the operation must be implemented by the backend or the operating system.

C interop

Foreign APIs are declared in vendored binding files with opaque, cstr and extern flow. Application code imports the binding file; it never needs a pointer type.

sdl2_min.loi
opaque SDL_Window

extern flow SDL_Init
    <- flags: u32
    => i32

extern flow SDL_CreateWindow
    <- title: cstr
    <- x: i32
    <- y: i32
    <- w: i32
    <- h: i32
    <- flags: u32
    => SDL_Window

extern flow SDL_DestroyWindow
    <- window: SDL_Window
FormMeaning
opaque NameA copyable foreign handle represented as void *; no fields or dereference.
cstrA const char * handle. A string literal may be passed or bound to it; arbitrary [u8] may not.
extern flow f ...A bodyless declaration resolved to a C symbol at link time.
extern flow f as c_f ...Calls a different symbol, such as a generated shim.

loi build ... --c-source shim.c --cc-flag -Ipath --cc-flag -lname compiles and links vendored C shims. Link flags are placed after the objects, so -l libraries resolve normally. For the vendored raylib 5.5 bindings:

terminal
loi build game.loi -o game \
    --c-source vendor/raylib/raylib_shim.c \
    --cc-flag -Ivendor/raylib/include \
    --cc-flag -lraylib \
    --cc-flag -lm

Generate bindings from a C header with the conservative binding generator:

terminal
python3 tools/bindgen/bindgen.py \
    --header vendor/sdl2/include/SDL2/SDL.h \
    --include vendor/sdl2/include \
    --include vendor/sdl2/include/SDL2 \
    --output vendor/sdl2/sdl2.loi \
    --shim vendor/sdl2/sdl2_shim.c \
    --skipped vendor/sdl2/skipped.txt \
    --module sdl2 --prefix SDL_

Complete pointer-free records become shapes; incomplete or unsafe records become opaque handles. Struct and out-parameter conversions go through a generated memcpy shim with _Static_assert layout checks. Callbacks, variadics, unions, bitfields, inline arrays, pointer-to-pointer, mutable char * buffers, wide strings and pointers to unsafe records are skipped and reported in skipped.txt. vendor/sdl2/ and vendor/raylib/ are complete worked examples.

CLI reference

The loi binary exposes the compiler pipeline directly. Paths are ordinary filesystem paths; outputs default to ./a.out, <stem>.o or lib<stem>.a.

CommandWhat it does
loi lex FILEPrints the token stream, one token per line.
loi parse FILEPrints the parsed program as a debug AST.
loi fmt FILEPrints canonical Flow Syntax to standard output.
loi check FILERuns the checker and ownership analysis; no output on success.
loi gen FILE [-o out.c]Prints or writes the generated C11 translation unit.
loi build FILE... [-o out]Checks, generates C, invokes cc and links the output.
loi clean FILE [-o out]Removes the output and its incremental stamp; does not read the source.

Build options

--debug / --releaseAdds -g or -O2 to the C compiler.

--emit-h FILEWrites a C header for exported declarations.

--emit-asm FILEDisabled: the assembly backend is an unfinished draft. The CLI rejects the flag with exit 2; use generated C or --emit-c.
--source-map FILEWrites source-map JSON Lines.
--arena-size BYTESSets the initial protect arena chunk size (default 64 MiB); the arena still grows as needed.
--cc-flag FLAGPasses an extra flag to cc; repeatable. Link flags follow the objects.

building.loi
# Inspect the generated C
loi gen examples/tictactoe.loi -o tictactoe.c

# Build an optimized executable and keep the C
loi build examples/tictactoe.loi -o tictactoe --release --emit-c tictactoe.c

# Reformat in place (the input is read before output is written)
loi fmt hello.loi > hello.formatted.loi && mv hello.formatted.loi hello.loi

# Multi-file build: one object per explicit input
loi build main.loi helpers.loi -o app

build invokes cc and ar. Set CC or AR to override them; both values may contain shell-like arguments (ccache cc, for example). A successful build leaves a .loi-stamp file next to the output so unchanged rebuilds are skipped.

Diagnostics are printed as path:line:column: message to standard error. check and build exit non-zero when any diagnostic is reported.

Playground server

terminal
cargo build

# open http://localhost:4173/playground.html

The server serves the static site and exposes POST /api/run, /api/check and /api/format. Each request writes the program to a temporary directory, copies lib/std.loi there so imports resolve, and runs the real loi binary. Set LOI_BIN to use a specific compiler, and PORT/HOST to change the listen address. It binds to 127.0.0.1 by default; it is a development tool, not a public sandbox.

Tic-tac-toe

The tic-tac-toe example is a deterministic demonstration rather than an interactive game: two heuristic players share the same turn logic, and after the self-play game the program also runs a fixed scripted game in which X completes the top row. Keeping the input fixed makes the output reproducible in tests and on the site.

tictactoe.loi
/// Return the third cell of a line when `player` already owns the other two.
/// In every other case the result is -1.
sealed flow winning_line
    <- board: [i32]
    <- first: i32
    <- second: i32
    <- third: i32
    <- player: i32
    => i32
{
    mut owned: i32 <- 0
    mut empty: i32 <- -1

    if board[first] == player {
        owned += 1
    }
    if board[second] == player {
        owned += 1
    }
    if board[third] == player {
        owned += 1
    }

    if board[first] == 0 {
        empty = first
    }
    if board[second] == 0 {
        empty = second
    }
    if board[third] == 0 {
        empty = third
    }

    if owned == 2 and empty >= 0 {
        => empty
    }
    => -1
}
Run it. loi build examples/tictactoe.loi -o tictactoe && ./tictactoe. The output ends with a draw and then a scripted X wins!.

Diagnostics

Diagnostics use the canonical glyphs: expects direction '->', found '<-', use of moved value 'p', shape 'Vec2' has no field 'nope'. Source positions are 1-based lines and columns, printed as file.loi:line:column: message.

Formally absent

  • No fun, interface, let, var, return, move, copy, visible or hidden.
  • No address-of (&x) or dereference (*p) operators and no pointers. & is only bitwise AND.
  • No brace shape literals (Vec2{ ... }) and no []T{ ... } slice literals.
  • No classes, methods, inheritance, exceptions, macros or implicit prelude.
  • No null/nil; use a flag or a sentinel.

Status & limits

Loi is a working compiler in Phase 4 (C backend). The language surface is stable enough to write real programs, but the implementation still has explicit provisional limits.

ComponentState
Lexer, parser, pretty-printerWorking; canonical Flow Syntax only. loi fmt preserves comments.
Type checkerWorking, including literal ranges, intrinsic signatures, bitwise/shift rules, shape cycle detection and canonical diagnostics.
Ownership analysisWorking: give liveness, definite assignment, exclusive <->, region escape checks, and allocating read intrinsics.
C backendWorking: one C11 translation unit, bounds checks, regions, checked arithmetic, bitwise/shift helpers, file/stdin I/O, numeric printing, source maps, headers, multi-file objects.
C interopWorking: opaque, cstr, extern flow, --c-source, and a header-to-Loi binding generator.
IR and assemblyDraft: --emit-ir emits IR text; --emit-asm is rejected because the assembly backend cannot generate runnable code yet. The C backend is the production path.
comptimeSpecified but not implemented: no constant evaluator or parser support yet.
Resources (guard)Specified, not implemented.

Known limitations

  • I/O is limited to whole-file and whole-stdin reads/writes plus numeric printing. There is no socket, directory, seek, environment or process API. read_file, read_stdin and read_line allocate in the current protect region and cannot escape it.
  • Imports are textual and cross-file visibility is not enforced. Multi-file builds give sealed flows external linkage so cross-file calls link.
  • Globals are limited to scalars, bool and [u8] initialized from a string literal. Composite globals await a runtime constructor.
  • A slice literal cannot escape the block that created it, including being returned or stored into an outer variable; allocate long-lived data in a protect region.
  • <- composite parameters are passed to C by value (slice headers still point at the caller's data). The checker forbids storing or returning the borrowed value, so the parameter stays observationally read-only.
  • loi fmt preserves // comments and is idempotent; comments inside multi-line expressions may move to the next statement boundary. Shape literals stay on one line.
  • Binding generation is conservative: callbacks, variadics, unions, bitfields, inline arrays, pointer-to-pointer, mutable char * buffers, wide strings and pointers to unsafe records need a hand-written shim.
  • The SDL2 and raylib 5.5 bindings and their shims are syntax-verified, but full link/run tests need a machine with those runtimes installed.
  • The playground executes code on the machine running the server. Run it locally and do not expose it as a public service.

Design decisions

The language is deliberately smaller than its feature list. These decisions explain what is in, what is out and why.

DecisionReason
Flow Syntax is the only surface. The migration is complete. Legacy keywords and forms were removed, not deprecated, so there is one spelling for every construct.
One owner, no lifetimes. Aliases are impossible by construction. give and clone make transfer and duplication explicit.
No pointers. Address-of would create a second name for one owner and require a lifetime system. Handles cover graphs; slices cover arrays.
Lexical regions. protect gives allocation a syntactic lifetime. There is no per-value destructor and no manual free.
Brackets are data, braces are scopes. Shape bodies, literals, slices and indexes use brackets. Blocks and regions use braces. The visual grammar matches the semantics.
Closed intrinsics plus a Loi library. A tiny backend surface keeps the compiler portable; everything else grows in lib/std.loi without changing the compiler.
sealed by default. Least privilege. open is the only way to export.
C11 backend. The generated output is inspectable, portable and easy to link. There is no VM and no hidden runtime.
Deterministic tic-tac-toe. Reproducible output makes the example testable and safe for the playground. Real programs can use the file and stdin intrinsics when they need external input.

Roadmap

Done

  • Foundation, lexer, parser, AST, formatter and diagnostics.
  • Shapes, flows, directions, bindings, control flow, casts, literals, globals and imports.
  • Ownership checks, definite assignment, exclusive directions and region escape analysis.
  • C11 code generation, runtime bounds checks, protect arenas, headers and source maps.
  • Multi-file builds, incremental stamps and the clean command.
  • Bitwise/shift operators, file/stdin I/O, numeric printing and comment-preserving fmt.
  • Canonical Flow Syntax migration and legacy cleanup.

In progress

  • Cross-file visibility enforcement and module semantics.
  • Composite globals through a runtime constructor.
  • IR and assembly backend completion.
  • Playground hardening and deployment documentation.

Next

  • comptime: parser support, a step-limited constant evaluator, and constant contexts for globals, defaults and extents.
  • The linear-resource design for guard and <Shape>_release.
  • Richer I/O once the resource model exists: directory, seek, socket and process APIs.
  • An interactive example that reads stdin; the deterministic tic-tac-toe example stays for reproducible tests.

Contributing

The project keeps a strict written protocol so that any contributor can resume without the previous conversation.

  1. Read development/LOI_SPEC.md before changing the language.
  2. Record status in development/PROGRESS.md and one-line decisions in development/DECISIONS.md.
  3. Keep the surface canonical: do not reintroduce legacy keywords, brace shape literals, []T{ ... } literals or &.
  4. Add or update tests for every behavior change and retire tests that only covered removed syntax.
  5. Do not silently rewrite working code. Verify with the compiler before claiming success.
  6. Keep the specification, examples and this website in sync with the implementation.
